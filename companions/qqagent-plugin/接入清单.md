# 接入清单 · QQ-agent 只当工具源

目标：**只有一个宿主说话**（DSH 这条鱼），QQ-agent 只提供插件工具 —— 它不参与收信、不发言。
否则同一个 QQ 号会被两个宿主同时回答，出现重复回答与节奏错乱。

## 前提

本机目前**没有装 QQ-agent**（`<QQ Agent 目录>` 不存在，只剩 `snowluma`）。以下步骤等它装回来再走。

## 步骤

### 1. 装回 QQ-agent，但别让它接 QQ

- 装好后先**不要**填 SnowLuma 的 token / 不要打开它的协议端连接。
- 按档案记录，它的配置在 `data\config.json`，里面有几项决定它参不参与 QQ：
  - `snowluma.*`（协议端地址与 token）
  - `allow.groups` / `allow.private`（白名单）
  - 发送队列 / SendQueue 相关开关（拟人节奏，属于"出嘴"那一半）
- **把白名单清空**（`allow.groups=[]`、`allow.private=[]`）：它就不会处理任何会话、也不回话。
  想更彻底：不填协议端 token，它连都连不上 QQ，只跑自己的插件运行时。
- ⚠️ 未验证：QQ-agent 的插件是否依赖"收到消息"才可用。如果某个插件是消息钩子而不是可调用工具，
  不接 QQ 它就不会触发 —— 这类插件不适合"只当工具源"，挑能直接被调用的那种。

### 2. 装配套插件

把 `companions/qqagent-plugin/` 放进 QQ-agent 的 `plugins/` 目录，然后：

- 设环境变量 `FISHWORLD_BRIDGE_TOKEN`（与 DSH 面板里生成的一致），或写进启动脚本；
- 可选 `FISHWORLD_BRIDGE_PORT`（默认 3211）；
- 重启 QQ-agent，日志里应出现 `[fishworld-borrow] 监听 http://127.0.0.1:3211`。

### 3. 补宿主侧注册

`index.js` 里的 `registerTools(registry)` 还是骨架：要按 QQ-agent 实际版本的插件 API，
把它的工具表取出来塞进去（`tools.set(name, { description, run })`）。
验收：`curl -H "Authorization: Bearer <token>" http://127.0.0.1:3211/tools` 能列出真插件工具。

### 4. DSH 这边

面板「AstrBot 接入」页 →「借手 · QQ Agent」卡：

1. 地址填 `http://127.0.0.1:3211`
2. 点「生成 token」，复制到 QQ-agent 那边（`FISHWORLD_BRIDGE_TOKEN`）
3. 点「试连」：应显示「连通了，QQ-agent 里有 N 个工具可借」
4. 打开「允许借手」

然后从鱼那边验一次：`fish_world(action="qqagent-tools")` 能看到同一张表，
`action="qqagent-tool", tool=..., params=...` 拿回来的是原始输出并标注 `[通过 QQ Agent 的 X 得到]`。

## 验收（三个都要过）

1. QQ-agent 的 `allow.groups` / `allow.private` 是空的，或它没连协议端 —— 群里只有鱼一个人在回
2. `/tools` 列得出真工具
3. 鱼调 `qqagent-tool` 拿到结果，且那条结果带着来源标注

## 回滚

- 关掉面板里的「允许借手」→ 鱼立刻调不到它
- 停掉 QQ-agent → 试连报「连不上」，鱼那边调工具会如实报错，不影响她正常聊天
