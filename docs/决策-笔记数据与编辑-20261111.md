# 决策稿 · 鱼的笔记：数据存哪、能不能编辑（2026-11-11）

> 状态：待主人拍板，未写代码。图二这种“功能缺失”最容易被当 UI bug 修三轮，先定数据存哪。

## 事实

- `NoteItem`（whale_data.dart L6-15）没有正文字段：只有 id / title / folder / mtime / src / srcKind / x / y / parent / links。
- 抽屉里的“正文”渲染的是 `title` 本身（pages.dart L713 / L732 重复）。
- 桥没有写通道：
  - `/fishworld/notes` 返回空 items（http.mjs L892）
  - `/fishworld/notes/move` 直接回「DSH 侧还没有笔记存储」（http.mjs L893）
- 结论：画布不能编辑不是 bug，是数据模型与桥都不支持。

## 三个选项

### a) DSH 侧新建笔记存储

- 做法：DSH 侧加读写接口，插件只做面板。
- 代价：要碰 DSH 体系，跨仓库；鱼世界面板只是客户端。
- 适合：笔记本来就该由 DSH 主程序拥有。

### b) 鱼世界数据仓（推荐）

- 做法：`fish-world/var/notes/…` 或 `鱼的世界/鱼的笔记/`，沿用现有 jsonl + 写前备份 + 回读校验 + 留痕。
- 优点：笔记是鱼自己整理的，落在鱼世界最自洽；复用现有写入纪律，不动 DSH。
- 代价：插件侧要补读写接口与文件迁移；面板要区分“新笔记仓”和旧快照。

### c) 承认是 DSH 只读导出物

- 做法：面板永不提供编辑；标题、画布、抽屉文案全改只读口径，删掉一切暗示可编辑的入口。
- 优点：零数据风险，改动最小。
- 代价：鱼的笔记永远只能“看结构”，不能整理。

## 若选 b：字段清单

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 稳定 id，不用标题当主键 |
| title | string | 标题，独立于正文 |
| body | string | 正文，Markdown / 纯文本先定一种 |
| summary | string | 摘要，可由正文截取，不 AI 现编 |
| parent | string | 父笔记 id，根为空 |
| folder | string | 分组 / 抽屉归类 |
| x / y | number | 画布坐标，保留现字段 |
| links | string[] | 关联笔记 id |
| createdAt | string | ISO 时间 |
| updatedAt | string | ISO 时间 |
| source | object | 来源（日记 / 对话 / 手动） |

标题与正文的关系：

- 现在两者是同一个值，必须拆开。
- 正文为空时标题仍可存在；标题为空时用正文首行兜底，只在显示层，不写回。
